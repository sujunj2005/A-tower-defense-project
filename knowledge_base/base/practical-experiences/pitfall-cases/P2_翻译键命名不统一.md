# P2：翻译键命名不统一导致显示异常

| 属性 | 值 |
|------|-----|

| **分类** | 翻译/国际化 |
| **严重程度** | 🟡 中 |
| **涉及文件** | `locale/translations.csv`、`data/events.json` |
| **知识库关联** | [翻译管理实践](../best-practices/翻译管理实践.md) |

---

## 现象

新增的 80+ 个事件选项在游戏中显示为原始键名字符串（如 `KEY_NAME_TEXT`），而非翻译后的中文文本。玩家看到的选项是技术键名，完全无法阅读。

## 根因

1. 事件系统升级时新增了大量选项，这些选项在 `events.json` 中的 `text` 字段直接使用了翻译键名
2. 但对应的 `translations.csv` 中未添加这些翻译键的映射
3. 部分翻译键命名不符合约定的 `_TEXT` 后缀规范，导致 CSV 与代码中的键名不匹配

本质上是在「数据定义 → 翻译表」之间缺少同步机制。

## 修复

1. 批量为所有新选项添加 `_TEXT` 后缀翻译键
2. 在 `translations.csv` 中补充 80+ 个选项翻译条目
3. 为新增 UI 字段（NPC 名称、职业名称、关系类型、事件变化描述）补充 30+ 个翻译键

```csv
# translations.csv 中新增
EVT_YOUNG_001_O1_TEXT,努力学习
EVT_YOUNG_001_O2_TEXT,外出冒险
NPC_LI_MING_NAME_TEXT,李明
PROF_SCHOLAR_NAME_TEXT,学者
RELATION_FRIEND_TEXT,朋友
```

## 预防

1. **翻译键命名规范**：
   - 选项文本 → `{OPTION_ID}_TEXT`
   - UI 标签 → `UI_{PURPOSE}_TEXT`
   - 数据展示 → `{MODULE}_{FIELD}_TEXT`
2. 新增任何显示文本前，先确认翻译键已在 CSV 中存在
3. 建立 `events.json` 与 `translations.csv` 的同步检查脚本
4. 使用 CI 或 pre-commit hook 自动验证翻译键完整性
