## 现象

技能系统配置中使用了 `npc_teacher_wang`、`npc_teacher_li` 等 NPC ID，用户反馈"这些 npc 没见过"，技能解锁条件因引用了不存在的 NPC 而永远无法满足。

## 根因

配置时基于叙事设计自行编造了 NPC ID，未先确认项目中真实存在的 NPC 实体。这是一种典型的"假设数据存在"错误 —— 凭想象构造引用，没有做存在性验证。

## 修复

通过搜索项目中所有 `npc_id` 字段，确认真实 NPC 列表：

```bash
# 搜索所有 NPC ID 定义
grep -roh '"npc_id":\s*"[^"]*"' --include="*.json" --include="*.gd" . | sort -u
```

确认真实 NPC 清单后，将所有技能配置中的 NPC ID 替换为真实存在的 ID。

## 预防

1. **任何引用项目已有数据时，必须先搜索确认实体是否存在**

   标准操作流程：
   ```
   需要引用 NPC/塔/事件/词条/职业 → 
   Step 1: Grep 搜索对应 ID → 
   Step 2: 确认存在且状态正确 → 
   Step 3: 在配置中使用确认过的 ID
   ```

2. **建立项目实体注册表**（`knowledge_base/` 中维护）

3. **配置验证脚本**：在启动时校验所有 NPC 引用目标的 `npc_id` 是否存在于真实 NPC 列表中，不存在的发出 `push_error`

## 教训

不要基于"应该有"来编造数据引用。项目中实体的增删改由特定流程控制，配置数据时必须验证引用的实体真实存在。这是一个跨系统的原则：NPC ID、塔 ID、词条 ID、事件 ID 等所有引用都必须做存在性验证。
