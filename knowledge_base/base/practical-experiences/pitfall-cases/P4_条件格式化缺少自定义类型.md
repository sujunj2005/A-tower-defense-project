# P4：事件条件格式化缺少自定义类型处理

## 现象

选项按钮上显示了特定条件的标签，但以下三种条件类型的条件文本显示为**空白**：

- `npc_relation` — NPC 好感度条件（如 "需要与李明好感度 >= 50"）
- `profession` — 职业要求条件（如 "需要职业：学者"）
- `profession_absent` — 职业缺失条件（如 "需要无职业"）

玩家看到的是空标签，不知道选择该选项需要满足什么条件。

## 根因

条件格式化函数 `_format_event_conditions()` 使用 `match` 语句处理各种条件类型，但只处理了基础属性条件（`attribute`、`trait`、`gold` 等），未为新添加的 `npc_relation`、`profession`、`profession_absent` 三种条件类型添加格式化分支。

当 `match` 无法匹配时，返回空字符串或未定义结果。

## 修复

在 `_format_event_conditions()` 中添加三种新条件类型的格式化分支：

```gdscript
func _format_event_conditions(requirements: Dictionary) -> String:
    var parts: Array[String] = []
    for key in requirements:
        match key:
            # ... 已有分支 ...
            "npc_relation":
                parts.append(_format_npc_relation_condition(requirements[key]))
            "profession":
                parts.append(_format_profession_condition(requirements[key]))
            "profession_absent":
                parts.append(_format_profession_absent_condition())
            _:
                parts.append(str(key) + ": " + str(requirements[key]))
    return ", ".join(parts)

# 新增格式化函数
func _format_npc_relation_condition(data: Dictionary) -> String:
    var npc_name := tr(data.get("npc_id", "") + "_NAME_TEXT")
    var relation_type := _get_relation_name(data.get("relation_type", 0))
    return tr("UI_REQUIRES_NPC_RELATION_TEXT") % [npc_name, relation_type, data.get("value", 0)]

func _format_profession_condition(prof_id: String) -> String:
    return tr("UI_REQUIRES_PROFESSION_TEXT") % [tr("PROF_" + prof_id + "_NAME_TEXT")]

func _format_profession_absent_condition() -> String:
    return tr("UI_REQUIRES_NO_PROFESSION_TEXT")
```

## 预防

1. **新增条件类型必须同步实现格式化函数** — 在 `_format_event_conditions()` 中添加对应的 `match` 分支
2. 格式化函数应返回可读的翻译文本，而非原始数据结构
3. 将条件格式化作为 OptionData 新增字段联动清单的第 4 项检查点
