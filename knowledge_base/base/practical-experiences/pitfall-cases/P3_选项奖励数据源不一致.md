## 现象

玩家选择选项后，后果弹窗只展示了 `rewards` 数组中的内容（如获得 trait、获得 gold），但以下新字段的数据完全没有出现在弹窗中：

- `gold_change`（金币变化）
- `attribute_changes`（属性变化）
- `trait_gains` / `trait_losses`（词条得失）
- `tower_gains` / `tower_losses`（防御塔得失）
- `npc_relation_changes`（NPC 好感变化）
- `profession_change` / `profession_lost`（职业变更）

导致玩家无从知晓选项的实际完整后果，严重影响游戏体验。

## 根因

事件系统升级时，`OptionData` Bean 新增了多个 flat 字段（独立字段而非嵌套在 rewards 数组中），但 UI 弹框的 `_show_consequence_popup()` 函数仍仅遍历 `rewards` 数组展示。两个数据流消费者（EventSystem.apply_rewards 和 EventUI._show_consequence_popup）未同步更新。

## 修复

在 `_show_consequence_popup()` 中合并所有数据源：

```gdscript
func _show_consequence_popup(option: OptionData) -> void:
    # 旧数据源
    for reward in option.rewards:
        _add_reward_item(reward)

    # 新 flat 字段
    if option.gold_change != 0:
        _add_gold_item(option.gold_change)
    for attr in option.attribute_changes:
        _add_attribute_item(attr, option.attribute_changes[attr])
    for trait_id in option.trait_gains:
        _add_trait_item(trait_id, true)  # 获得
    for trait_id in option.trait_losses:
        _add_trait_item(trait_id, false)  # 失去
    # ... 同样处理 tower_gains/losses、npc_relation_changes、profession 等
```

## 预防

1. **OptionData 新增字段必须联动更新 6 处消费者**：
   - Bean 定义 (`option_data.gd`)
   - `EventSystem.apply_rewards()`
   - UI 弹框 `_show_consequence_popup()`
   - 条件检查 `option_system.check_requirements()`
   - `translations.csv` 翻译键
   - 测试用例
2. 使用 [数据流变更联动清单](../best-practices/数据流规范.md) 逐项检查
3. 编写单元测试验证 `_show_consequence_popup` 展示所有字段类型
