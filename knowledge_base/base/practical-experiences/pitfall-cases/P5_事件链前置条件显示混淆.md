# P5：事件链前置条件显示混淆

## 现象

在游戏 UI 中展示事件链前置条件时，内部使用的 `flag:` 前缀标志位被当作普通事件名称显示，例如：

- 系统中约定 `flag:event_chain_A_completed` 是内部链标志位
- UI 直接展示了 `flag:event_chain_A_completed` 这个原始字符串
- 玩家看到无意义的 `flag:` 前缀文本，造成困惑

## 根因

`_format_chain_prerequisites()` 函数在格式化前置条件时，未区分内部数据标记（`flag:` 前缀）和外部事件 ID。将所有 `chain_prerequisites` 数组中的条目平等对待，直接拼接展示。

这类 `flag:` 前缀是内部数据结构约定，用于在事件系统逻辑中追踪事件链状态，不应暴露给玩家。

## 修复

在格式化时过滤掉 `flag:` 前缀的内部标志位：

```gdscript
func _format_chain_prerequisites(prerequisites: Array) -> String:
    var visible_ids: Array[String] = []
    for prereq in prerequisites:
        var s := str(prereq)
        if s.begins_with("flag:"):
            continue  # 跳过内部标志位，不对外展示
        visible_ids.append(s)

    if visible_ids.is_empty():
        return ""  # 无可展示的前置条件
    return "需要先完成: " + ", ".join(visible_ids.map(func(id): return tr(str(id) + "_TEXT")))
```

## 预防

1. **内部数据结构不直接暴露给 UI 层** — 所有 `flag:`、`chain_`、`_internal` 等前缀的数据都应过滤
2. UI 层需要展示人类可读的翻译文本，而非系统内部标识符
3. 设计约定：内部标识使用统一前缀（如 `flag:`、`internal:`）便于过滤
4. 在格式化函数中添加内部前缀过滤作为模板逻辑
