## 现象

玩家在事件界面选择一个选项后，游戏直接崩溃。崩溃发生在选项按钮回调 `_on_option_pressed()` 执行过程中。

Godot 报错类似：
```
Invalid access to property or key 'xxx' on a previously freed instance.
Attempt to call function 'xxx' in base 'null instance' on a null instance.
```

## 根因

`_on_option_pressed()` 回调中先调用了 `queue_free()` 释放自身节点，随后又尝试访问 `/root/EventSystem` 等外部全局节点。但 `queue_free()` 执行后，节点的 `is_inside_tree()` 状态已变为 `false`，此时通过 `get_node()` 访问外部节点可能导致空引用或无效访问。

核心问题：**未检查 `is_inside_tree()` 状态**就访问了全局单例节点。

```gdscript
# 错误代码
func _on_option_pressed(index: int) -> void:
    queue_free()
    # 以下代码在节点退出场景树后执行，可能崩溃
    var event_system := get_node("/root/EventSystem") as EventSystem
    event_system.select_option(index)
```

## 修复

在访问外部节点前添加 `is_inside_tree()` 检查：

```gdscript
# 正确代码
func _on_option_pressed(index: int) -> void:
    # 先保存必要数据（在释放前）
    var selected_index := index

    # 释放自身
    queue_free()

    # 安全检查：如果已不在场景树中，通过 AutoLoad 路径仍然可以访问
    if not is_inside_tree():
        var event_system := Engine.get_main_loop().root.get_node("EventSystem") as EventSystem
        if event_system:
            event_system.select_option(selected_index)
        return
```

更好的模式是**先执行业务逻辑，再释放**：

```gdscript
func _on_option_pressed(index: int) -> void:
    # 1. 先执行业务逻辑
    var event_system := get_node("/root/EventSystem") as EventSystem
    if event_system:
        event_system.select_option(index)

    # 2. 最后释放
    queue_free()
```

## 预防

1. **在信号回调/异步操作中访问 `/root/XXX` 全局节点前必须调用 `is_inside_tree()`**
2. 调用 `queue_free()` 后立即 `return`，不在之后访问任何成员变量或调用方法
3. 优先使用「先业务后释放」的代码顺序，将 `queue_free()` 放在函数末尾
4. 必要时使用 `Engine.get_main_loop().root` 替代 `get_node("/root/...")` 作为备用路径
