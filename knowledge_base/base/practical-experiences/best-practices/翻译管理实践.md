# 翻译管理实践

本项目的国际化系统使用 CSV 翻译表 + `tr()` 函数实现。

## 🔴 强制规范

### 1. 翻译键命名一致性

所有翻译键必须遵循统一命名规范：

| 用途 | 命名格式 | 示例 |
|------|---------|------|
| 选项按钮文本 | `{OPTION_ID}_TEXT` | `EVT_YOUNG_001_O1_TEXT` |
| UI 标签 | `UI_{PURPOSE}_TEXT` | `UI_CONFIRM_TEXT`, `UI_BACK_TEXT` |
| 数据展示 | `{MODULE}_{FIELD}_TEXT` | `NPC_LI_MING_NAME_TEXT` |
| 系统提示 | `SYS_{TYPE}_TEXT` | `SYS_SAVE_SUCCESS_TEXT` |
| 安静年文本 | `QUIET_YEAR_{N}` | `QUIET_YEAR_1` ~ `QUIET_YEAR_6` |

### 2. 翻译键定义流程

```
1. 在代码中使用 tr("KEY_NAME")
2. 在 locale/translations.csv 中添加对应行
3. 确保 zh（中文）列为翻译文本，en 列可选填英文
4. 运行项目验证翻译显示正常
```

```gdscript
# 正确：使用 tr() 函数
label.text = tr("OPTION_TEXT_01")
# 带参数
label.text = tr("GOLD_FORMAT") % [amount]

# 错误：直接硬编码字符串
label.text = "选择选项"  # 无法国际
```

## 🟡 建议规范

### 3. CSV 翻译表管理

CSV 格式：
```
keys,en,zh
WELCOME_MESSAGE,"Welcome","欢迎"
UI_CONFIRM_TEXT,"Confirm","确认"
EVT_YOUNG_001_O1_TEXT,"Study hard","努力学习"
```

- keys 列为翻译键标识
- zh 列为必填（主要目标语言）
- en 列为可选的英文翻译
- 修改 CSV 后需重启编辑器或重新加载项目

### 4. 新增事件的翻译键清单

每个新事件及其选项需要以下翻译键：

```
# 事件本身
EVENT_{ID}_TITLE     — 事件标题
EVENT_{ID}_DESC      — 事件描述

# 每个选项
{OPTION_ID}_TEXT     — 选项文本

# 选项后果中涉及的新名词
NPC_{NPC_ID}_NAME_TEXT    — NPC 名称
PROF_{PROF_ID}_NAME_TEXT  — 职业名称
RELATION_{TYPE}_TEXT      — 关系类型标签
```
