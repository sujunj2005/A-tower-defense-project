# 数据流规范

本项目数据流规范确保 JSON 配置、Bean 对象、系统逻辑、UI 展示之间的同步一致性。

## 🔴 强制规范

### 1. OptionData 字段联动更新清单

当在 OptionData Bean 或 events.json 中新增字段时，必须按以下清单逐项验证：

```
新增字段联动检查清单：

□ 1. Bean 定义更新
    文件：scripts/bean/option_data.gd
    内容：@export var xxx + to_dict() 导出 + from_dict() 解析

□ 2. JSON 配置更新
    文件：data/events.json
    内容：所有相关选项添加新字段

□ 3. 奖励应用更新
    文件：scripts/logic/life_simulation/event_system.gd
    函数：apply_rewards() 处理新字段

□ 4. UI 展示更新
    文件：scripts/ui/event_ui.gd
    函数：_show_consequence_popup() 展示新字段
    函数：_format_event_conditions() 格式化新条件类型

□ 5. 翻译键补充
    文件：locale/translations.csv
    内容：新字段对应的翻译键

□ 6. 测试用例更新
    文件：tests/unit/test_event_system_v2.gd 等
    内容：覆盖新字段的测试场景
```

### 2. JSON 配置数据流

```
data/events.json
    ↓ 加载
ConfigManager / EventSystem
    ↓ 解析
OptionData Bean (from_dict)
    ↓ 使用
EventSystem.apply_rewards() → SessionData
    ↓ 展示
EventUI._show_consequence_popup()
```

## 🟡 建议规范

### 3. events.json 字段完整性

每个选项（option）的最小必含字段集：

```json
{
    "option_id": "EVT_XXX_O1",
    "text": "基础文本（fallback）",
    "requirements": {},
    "rewards": [],
    "gold_change": 0,
    "attribute_changes": {},
    "trait_gains": [],
    "trait_losses": [],
    "tower_gains": [],
    "tower_losses": [],
    "npc_relation_changes": [],
    "profession_change": "",
    "profession_lost": false
}
```

### 4. 数值平衡原则

防御塔奖励配置原则：
- 青年期事件：大量 tower_gains（体现成长阶段优势）
- 中年期事件：部分 tower_gains（体现积累和权衡）
- 小数值配置：tower_gains 1-3 个
- 大数值配置：tower_gains 3-6 个
- 每个选项都应检查 tower_gains 是否存在缺失
