# 事件系统模式

本项目的核心系统——人生模拟事件系统（EventSystem），管理事件触发、选项展示、后果执行。

## 🔴 强制规范

### 1. 数据结构变更联动

变更选项字段时按用途核对这些入口。只在字段确实参与该环节时更新对应实现。

| 序号 | 位置 | 说明 |
|------|------|------|
| 1 | `scripts/bean/option_data.gd` | Bean 定义：添加 `@export var` 字段 + `to_dict()` + `from_dict()` 处理 |
| 2 | `scripts/logic/life_simulation/event_system.gd` | `select_option()` 的结算顺序及对应后果处理 |
| 3 | `scripts/ui/event_ui.gd` | `_show_consequence_popup()` 展示逻辑 |
| 4 | `scripts/logic/life_simulation/option_system.gd` | `check_requirements()` 条件检查 |
| 5 | `locale/translations.csv` | 翻译键补充 |
| 6 | `tests/unit/` 相关测试 | 测试用例更新 |

### 2. 奖励数据合并展示

`_show_consequence_popup()` 必须合并展示以下所有数据源：

```gdscript
# rewards 旧数组 + 所有新 flat 字段
func _show_consequence_popup(option: OptionData) -> void:
    _add_rewards_from_array(option.rewards)           # 旧 rewards 数组
    _add_gold_change(option.gold_change)              # 金币变化
    _add_attribute_changes(option.attribute_changes)  # 属性变化
    _add_trait_changes(option.trait_gains, option.trait_losses)  # 词条
    _add_tower_changes(option.tower_gains, option.tower_losses)  # 防御塔
    _add_npc_changes(option.npc_relation_changes)     # NPC 好感
    _add_profession_change(option.profession_change, option.profession_lost)  # 职业
```

## 🟡 建议规范

### 3. 条件格式化函数模式

每个条件类型必须对应一个格式化分支，返回可读翻译文本：

```gdscript
func _format_condition(key: String, value: Variant) -> String:
    match key:
        "attribute":
            return _format_attribute_condition(value)
        "trait":
            return _format_trait_condition(value)
        "gold":
            return _format_gold_condition(value)
        "family_background":
            return _format_family_condition(value)
        "npc_relation":
            return _format_npc_relation_condition(value)  # 新条件类型
        "profession":
            return _format_profession_condition(value)    # 新条件类型
        "profession_absent":
            return _format_profession_absent_condition(value)  # 新条件类型
        _:
            return "未知条件: %s" % key
```

### 4. 内部数据不暴露给 UI

内部数据结构（如 `flag:` 前缀的标志位、`chain_flag` 等）不应直接展示给用户：

```gdscript
# 正确：过滤内部标志位
func _format_chain_prerequisites(prerequisites: Array) -> String:
    var visible_events: Array[String] = []
    for prereq in prerequisites:
        var s := str(prereq)
        if s.begins_with("flag:"):
            continue  # 跳过内部标志位，不展示
        visible_events.append(s)
    return ", ".join(visible_events)
```

### 5. 事件配置检查清单

事件的选项直接定义在 `data/events.json` 的 `options` 中。写入稳定的 `option_id` 和存在于翻译表的 `text`。门槛与后果按需填写，解析时对缺省字段使用默认值。同一笔金币或属性变化选择一个结算字段。编辑后核对选项条件、实际结算和后果弹窗。
