## 1. 条件系统踩坑

### 1.1 conditions Array[Dictionary] 在 Resource 中的序列化

Godot 4.6.2 支持 `Array[Dictionary]`。项目通过 `EventData.from_dict()` 从 JSON 读入条件，逐项追加到声明为 `Array[Dictionary]` 的属性。JSON 本身没有 GDScript 数组元素类型元数据。已有数组的内容类型兼容时，也可以用 `typed_array.assign(raw_array)` 复制，手动逐项追加便于同时校验数据。直接给强类型数组属性赋普通 `Array` 会发生类型不匹配。[当前反序列化](../../scripts/bean/event_data.gd) · [Godot Array 类参考](../base/godot-official-docs/classes/class_array.rst)

### 1.2 通用条件表达式的 op 运算符

**问题**: 条件表达式中 `op` 运算符（如 `>=`、`==`、`<`）未设置默认值时为空字符串，导致 `_compare_op()` 方法报错或返回错误结果。

**根因**: `op` 字段在 JSON 配置中可能遗漏，空字符串不是合法运算符。

**解决方案**:
```gdscript
# ❌ 错误：op 可能为空
var op: String = condition.get("op", "")  # 空字符串，_compare_op 报错！

# ✅ 正确：默认值设为 ">=" 避免空值报错
var op: String = condition.get("op", ">=")

# ✅ _compare_op 方法需处理未知运算符的 fallback
func _compare_op(left: Variant, op: String, right: Variant) -> bool:
    match op:
        ">=": return left >= right
        "<=": return left <= right
        ">": return left > right
        "<": return left < right
        "==": return left == right
        "!=": return left != right
        _:
            push_warning("未知运算符: %s，回退到 >=" % op)
            return left >= right
```

**规则**: 🟡 **建议** —— `op` 运算符默认值设为 `">="`，`_compare_op()` 必须有未知运算符的 fallback 分支。

### 1.3 AND 逻辑中条件数量与性能

主筛选依次检查年龄、阶段、事件链、家庭背景和事件条件。条件数组按 AND 短路，项目没有 3–5 项的固定上限。列表较长时，把条件写成可核实的配置，并用正反用例验证。

### 2.1 选项后果字段的默认值

`OptionData.to_dict()` 始终返回 `option_id`、`text`、`requirements`、`rewards`，非空或非默认的后果另外写入。消费方应使用对应默认值，新增字段时要同时核对 `from_dict()`、`to_dict()`、事件结算和弹窗显示。

### 2.3 tower_losses 直接 erase Dictionary 中的键

**问题**: `tower_losses` 的处理逻辑是直接 `erase` towers Dictionary 中的键，不处理 `count=0` 的情况。

**根因**: 设计上 `tower_losses` 是要完全移除某种塔，而非减少数量。如果需要减少数量而非移除，需额外逻辑。

**解决方案**:
```gdscript
# 当前实现：直接 erase 移除整类塔
for tower_id: String in consequence.tower_losses:
    session.towers.erase(tower_id)

# 如果需要支持"减少数量而非移除"，需额外判断
for tower_id: String in consequence.tower_losses:
    var loss_count: int = consequence.tower_losses[tower_id]
    if tower_id in session.towers:
        var current: int = session.towers[tower_id]
        var remaining: int = current - loss_count
        if remaining <= 0:
            session.towers.erase(tower_id)  # 数量归零则移除
        else:
            session.towers[tower_id] = remaining
```

**规则**: 🟡 **建议** —— `tower_losses` 应明确语义是"移除"还是"减少数量"，当前实现为"移除"。如需支持"减少数量"，需增加 `count` 字段处理逻辑。

### 2.4 profession_lost 与 profession_change 的互斥逻辑

**问题**: `profession_lost` 与 `profession_change` 不应同时为 true/非空，逻辑上应先处理 lost 再处理 change。

**根因**: 两者同时生效时语义冲突——先失去职业再更换职业，还是更换职业时自动失去旧职业？

**解决方案**:
```gdscript
# ❌ 错误：同时设置 profession_lost 和 profession_change
{
    "profession_lost": "warrior",
    "profession_change": "mage"
}

# ✅ 正确：只设置 profession_change，逻辑上自动包含 lost
{
    "profession_change": "mage"  # 更换职业时自动失去旧职业
}

# ✅ 如果确实需要"失去职业但不更换"：
{
    "profession_lost": "warrior"  # 仅失去，不更换
}

# ✅ 处理顺序：先 lost 再 change
func _apply_consequence(consequence: ConsequenceData) -> void:
    if consequence.profession_lost != "":
        _remove_profession(consequence.profession_lost)
    if consequence.profession_change != "":
        _change_profession(consequence.profession_change)
```

**规则**: 🔴 **强制** —— `profession_lost` 与 `profession_change` 不应同时为非空。处理顺序必须先 `lost` 再 `change`。更换职业时只需设置 `profession_change`，无需同时设置 `profession_lost`。

## 3. 加权随机踩坑

### 3.1 动态权重计算中修正因子可能为0

当前主路径在候选为空时直接返回 `null`。`matches_event_chain()` 会在入池时排除已完成或已锁定事件。若传入非空候选且总权重小于等于零，`_weighted_random_select()` 会返回第一个候选。本地用两个零权重候选复测了这个行为。

这一分支避免后续用最大权重做除法时除零。浮点乘法 `randf() * 0.0` 本身是合法运算。[候选筛选与权重抽取](../../scripts/logic/life_simulation/event_system.gd)

### 3.2 权重浮点精度问题

事件基础权重在反序列化时至少为 1。动态修正先以浮点数相乘，再向上取整并以零为下限，最终传给抽取器的是整数权重。配置时应检查修正因子与结果是否符合预期，不必把实际抽取代码理解为浮点累加轮盘。[事件权重实现](../../scripts/logic/life_simulation/event_system.gd) · [事件解析](../../scripts/bean/event_data.gd)

### 3.3 权重为零时的候选顺序

当前零总权重时的回退是确定性地取首项，因此候选排列影响结果。若希望零权重表示全部禁止或改成等概率抽取，应修改代码并用单测定义这一语义。[权重抽取实现](../../scripts/logic/life_simulation/event_system.gd)

## 4. NPC系统踩坑

### 4.1 NPCData Resource 数组在 SessionData 中的序列化

**问题**: `NPCData` 是自定义 Resource，作为 `SessionData` 的 `npcs: Array[NPCData]` 字段存储。直接 `to_dict()` 时 Resource 数组无法自动序列化为字典数组。

**根因**: Godot 的 `JSON.stringify()` 不支持直接序列化 Resource 对象，需要手动转换为 Dictionary。

**解决方案**:
```gdscript
# ❌ 错误：直接序列化 Resource 数组
func to_dict() -> Dictionary:
    return {"npcs": npcs}  # npcs 是 Array[NPCData]，JSON 无法处理！

# ✅ 正确：使用 _npcs_to_array() 辅助方法转成字典数组
func _npcs_to_array() -> Array[Dictionary]:
    var result: Array[Dictionary] = []
    for npc: NPCData in npcs:
        result.append(npc.to_dict())
    return result

func to_dict() -> Dictionary:
    return {"npcs": _npcs_to_array()}
```

**规则**: 🔴 **强制** —— Resource 数组序列化时必须通过辅助方法逐个调用 `to_dict()` 转换为字典数组。

### 4.2 NPC 好感度边界值处理

**问题**: NPC 好感度应在 0-100 范围内，但加减操作可能导致溢出（负数或超过100）。

**解决方案**:
```gdscript
# ❌ 错误：好感度可能溢出
npc.affection += value  # 可能 < 0 或 > 100

# ✅ 正确：使用 clampi 限制范围
npc.affection = clampi(npc.affection + value, 0, 100)
```

**规则**: 🔴 **强制** —— NPC 好感度修改必须使用 `clampi(affection + value, 0, 100)` 限制范围。

## 5. 事件链踩坑

### 5.1 检查事件链前置引用

`chain_prerequisites` 要求每项前置都满足。非空的 `chain_prerequisites_any` 要求其中至少一项满足。两组同时存在时分别检查。

- 事件 ID 必须存在于事件池，运行时从已完成事件中查找。
- `flag:标记名` 必须对应某个事件选项可写入的 `chain_flag`，运行时从已记录的选择标记中查找。

配置引用由单测检查。分支可达性测试还验证了选中不同选项后，普通事件抽取和临近年龄回退都能正确识别前置条件。[前置检查实现](../../scripts/bean/event_data.gd) · [引用校验](../../tests/unit/test_config_cross_reference.gd) · 事件链回归测试（本地 `tests/unit/test_life_event_chains.gd`）

---

### 5.2 分支前置与互斥

`chain_excludes` 会在列表中的任一事件已完成时阻止当前事件入池。若两个分支各自满足前置且都未完成，二者可以同时成为候选。需要让玩家先前的决定立即限定后续时，应为各分支配置对应的选择标记。需要汇合时，用 `chain_prerequisites_any` 接受任一有效前置。

当前 TestMCP 的 `trigger_chance` 条件会被略过。普通事件在通过资格筛选后，根据 `weight` 及动态修正进行加权抽取。分支互斥由前置、选择标记和已完成记录决定，因此配置无需校验各分支的 `trigger_chance` 之和。[事件筛选与抽取](../../scripts/logic/life_simulation/event_system.gd) · [互斥检查](../../scripts/bean/event_data.gd)

---

### 5.3 事件链中断与可达性

前置事件可能因年龄窗、阶段、选择标记或抽取结果未完成。策划应为必须可达的节点预留年龄窗口，或用 `chain_prerequisites_any` 配置可汇合的前置；保留必选前置时，需按同一局的真实选择顺序验证。

当前没有通用的事件链超时补发。压力到期可以写入 `unlocked_events`，这一记录只给已具备资格的事件加权。回退候选仍检查事件链，也无法替代缺失的前置。[事件链实现](../../scripts/bean/event_data.gd) · [压力到期及抽取](../../scripts/logic/life_simulation/event_system.gd) · 现有回归（本地 `tests/unit/test_life_event_chains.gd`）

## 6. 选项系统与家庭成员踩坑

### 6.1 选项职业条件否定前缀解析（§E17）

**问题**: 选项系统的 `requirements` 字典中 `profession` 字段仅支持正向匹配（如 `"programmer"`），不支持否定条件（如 `"!programmer"` 表示"非程序员"）。

**根因**: 条件检查逻辑直接使用 `==` 比较，未解析条件字符串的 `!` 前缀符号。

**解决方案**:
```gdscript
# option_system.gd — 选项职业条件检查
elif attr_name == "profession":
    var prof_value: String = str(required_value)
    if prof_value.begins_with("!"):
        var excluded_prof: String = prof_value.substr(1)
        if session.current_profession == excluded_prof:
            return false  # 否定条件：玩家是该职业则不满足
    else:
        if session.current_profession != prof_value:
            return false  # 正向条件：玩家必须是该职业
```

**数据来源**: `options.json` 中 `"profession": "!programmer"`（第3459行）
**相关代码**: [option_system.gd](../../scripts/logic/life_simulation/option_system.gd#L86-L94)、[event_ui.gd](../../scripts/ui/event_ui.gd#L85-L93)、[event_system.gd](../../scripts/logic/life_simulation/event_system.gd#L492-L502)

**规则**: 🔴 **强制** —— 选项系统的 `requirements.profession` 条件检查必须支持 `!` 前缀表示否定条件。同一逻辑在 `option_system.gd`、`event_ui.gd`、`event_system.gd` 三处必须保持一致。

### 6.3 选项 family_effect 字段更新家庭成员状态（§E19）

**问题**: 选项数据中缺少更新家庭成员状态的机制。

**根因**: 选项字典中未定义 `family_effect` 字段来描述选择该选项后对家庭成员状态的影响。

**解决方案**:

```gdscript
# option_data.gd — 选项数据字段定义
@export var family_effect: Variant = {}

# to_dict 中条件序列化
var fx = family_effect
if fx is Dictionary and not fx.is_empty():
    result["family_effect"] = fx
elif fx is Array and not fx.is_empty():
    result["family_effect"] = fx

# from_dict 中反序列化（支持 Dictionary 和 Array 两种类型）
var raw_fx = data.get("family_effect", {})
if raw_fx is Array:
    opt.family_effect = raw_fx
else:
    opt.family_effect = Dictionary(raw_fx)
```

**family_effect 数据格式示例**:
```json
{
    "member_id": "spouse",
    "alive_change": 0,
    "mood_change": 5
}
```

**相关代码**: [option_data.gd](../../scripts/bean/option_data.gd#L17)（第17行定义）、[option_data.gd](../../scripts/bean/option_data.gd#L51-L55)（to_dict序列化）、[option_data.gd](../../scripts/bean/option_data.gd#L100-L104)（from_dict反序列化）

**规则**: 🔴 **强制** —— 选项数据中需要影响家庭成员状态时，必须使用 `family_effect` 字段描述影响（支持 `alive_change` 等子字段）。`family_effect` 支持 Dictionary 和 Array 两种类型。

### 6.4 event_ui.gd 中 /root 路径访问前必须检查 is_inside_tree()（§E20）

**问题**: `event_ui.gd` 的 `_on_option_pressed()` 中，在调用 `EventSystem.select_option()` 后继续使用 `get_node_or_null("/root/...")` 访问全局节点。`select_option()` 可能触发场景切换（如进入 BATTLE 阶段），导致当前节点被移出场景树，触发 `Can't use get_node() with absolute paths from outside the active scene tree` 错误。

**根因**: `select_option()` 可能触发状态切换，将 EventUI 从场景树中移除，后续对 `/root` 绝对路径的访问在节点已不在场景树时报错。

**解决方案**:
```gdscript
# event_ui.gd — _on_option_pressed 方法
func _on_option_pressed(index: int) -> void:
    if not is_inside_tree():
        return  # 前置安全检查
    var options: Array = _current_event.options
    if index < 0 or index >= options.size():
        return
    var selected_option: OptionData = options[index]
    var es: Node = get_node_or_null("/root/EventSystem")
    if es and es.has_method("select_option"):
        es.select_option(_current_event.to_dict(), selected_option.to_dict())
    # ⚠️ select_option 可能触发场景切换，必须再次检查
    if not is_inside_tree():
        return  # 场景已切换，安全退出
    # 后续安全的节点访问...
    var rewards: Array = selected_option.rewards
    for reward: Dictionary in rewards:
        if reward.get("type", "") == "trait":
            var ach_sys: Node = get_node_or_null("/root/AchievementSystem")
            if ach_sys and ach_sys.has_method("on_trait_acquired"):
                ach_sys.on_trait_acquired(reward.get("id", ""))
```

**相关代码**: [event_ui.gd](../../scripts/ui/event_ui.gd#L314-L333)（第314-333行）

**规则**: 🔴 **强制** —— 在 `event_ui.gd` 等可能被场景切换影响的 UI 脚本中，调用可能触发场景切换的方法（如 `EventSystem.select_option()`）之后，必须立即检查 `is_inside_tree()`，确认节点仍在场景树中才能继续访问 `/root` 路径。

**相关踩坑** [§51 节点被移出场景树后调用 get_node_or_null 报错](../wiki/guides/common-pitfalls.md#51-节点被移出场景树后调用get_node_or_null报错--高)

### 6.5 翻译键使用规范：选项文本与特质翻译键前缀分离（§E21）

**问题**: 选项文本使用 `TRAIT_` 前缀的翻译键，特质使用 `OPTION_` 前缀，翻译键前缀混用导致语义混乱、翻译文件管理困难、后续维护成本高。

**根因**: 添加翻译键时未遵循统一的前缀约定。

**统一翻译键前缀规范**:

| 内容类型 | 翻译键前缀 | CSV 文件 | 示例 |
|---------|-----------|---------|------|
| 选项文本 | `OPTION_` | `options.csv` | `OPTION_EVENT_LETTER_TEXT` |
| 特质名称 | `TRAIT_` | `traits.csv` | `TRAIT_QUICK_LEARNER_NAME` |
| 特质描述 | `TRAIT_` | `traits.csv` | `TRAIT_QUICK_LEARNER_DESC` |
| 事件名称 | `EVENT_` | `events.csv` | `EVENT_MATH_CONTEST_NAME` |

```gdscript
# ❌ 错误：选项文本使用 TRAIT_ 前缀
```
