# 游戏平衡踩坑记录

## 1. 护甲减伤代码不一致

**问题：** `enemy_config.gd` 中 light=10%/heavy=35%，但 `enemy_data.gd` 中 light=20%/heavy=40%
**影响：** 敌人实际减伤与配置不符，导致平衡数据不可信
**解决：** 统一为 enemy_config.gd 的值（light=10%, heavy=35%）
**教训：** 多处定义同一逻辑时，必须确保一致性。应只在一处定义护甲映射，其他地方引用

## 2. TowerBean 默认值与 JSON 数据不一致

**问题：** `tower_bean.gd` 中 sell_ratio 默认 0.5，但 JSON 中大部分塔为 0.7；damage_growth 默认 0.2，但 JSON 中 0.08~0.2
**影响：** 新增塔时如果忘记在 JSON 中指定这些字段，会使用错误的默认值
**解决：** 将默认值调整为 JSON 中的主流值（sell_ratio=0.7, damage_growth=0.12）
**教训：** Bean 的默认值应与 JSON 数据的主流值一致，而非使用任意值

## 3. 塔精简后事件引用更新流程

**问题：** 从24种塔精简到14种时，events.json 和 options.json 中有大量旧塔ID引用
**影响：** 运行时事件选项引用不存在的塔ID，导致 tower_gains/tower_losses 无效
**解决：** 建立旧ID→新ID映射表，用 Python 脚本批量替换所有 JSON 文件中的引用
**教训：** 大规模ID重命名时，必须建立映射表并自动化替换，手动替换容易遗漏

## 4. 全图攻击塔的平衡方式

**问题：** 全图攻击塔（range=9999）如果不限制，会导致游戏过于简单
**解决：** 通过极低攻速(0.5)、适中伤害(30)、低卖出比(0.5)来平衡。全图塔的DPS仅为15，远低于同价位塔
**教训：** 全图攻击塔必须通过多个维度限制：攻速、伤害、费用、卖出比

## 5. old_age 经济调整

**问题：** old_age 阶段金币倍率1.0但战斗难度3.0，经济严重紧张
**解决：** 将 gold_multiplier 从1.0提升到1.5，并新增 stage_gold_bonus(old_age=40)
**教训：** 高难度阶段必须同步提升经济收入，否则玩家无法维持防御

## 6. Boss 阶段性机制实现注意事项

**问题：** Boss 的 phase_2/judgment 等阶段性机制需要在敌人视图中实现触发逻辑
**解决：** 在 enemies.json 中定义 trigger 条件（health_below），在 enemy.gd 中检查并触发
**教训：** Boss 机制需要 JSON 配置和代码实现配合，配置只定义参数，逻辑在代码中
