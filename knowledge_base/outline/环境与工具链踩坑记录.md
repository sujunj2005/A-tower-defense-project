## §T1 Windows 下 localhost 走 IPv6 ::1 黑洞，Docker 服务请求固定 5s 超时

**🔴 强制**

- **症状**：连 Docker 暴露的服务（数据库/API）极慢或超时；请求耗时恒定 5 秒左右
- **结论**：Windows 连 Docker 端口**永远用 `127.0.0.1`，禁止 `localhost`**（localhost 优先解析 ::1，Docker 转发仅 IPv4，静默丢包等超时）
- **适用**：所有 docker run -p / Docker Desktop 场景；Python/PowerShell/任意 HTTP 客户端
- **关联排查口诀**：请求耗时恒定整秒 = 超时重试特征 → 先查网络栈再查服务；系统代理开着就先 `--noproxy "*"` 排除

详细排查过程与证据：[T1 原始复盘](../base/practical-experiences/pitfall-cases/T1_Win_localhost_IPv6黑洞导致Docker服务请求5s超时.md)

## §T2 Qdrant/rag 管道操作要点

**🟡 建议**

- 全量重建用 `python rag_ingest.py --force`，**禁止手删 `.rag_manifest.json` 后跑增量**（账本会让空库判定"无变更"跳过一切）
- 中文语料 embedding 用 `BAAI/bge-small-zh-v1.5`（512 维）；换模型必换 `EMBEDDING_DIM`
- HuggingFace 下载慢/超时：`$env:HF_ENDPOINT="https://hf-mirror.com"`；已缓存模型用 `HF_HUB_OFFLINE=1` 跳过联网校验
- 观察灌入真实进度：直接查 Qdrant REST `/collections/<name>` 的 points_count，别信重定向后的 stdout（块缓冲）
- PowerShell 给 curl.exe 传 JSON 体引号会被吞，写临时文件 `-d "@file"`
