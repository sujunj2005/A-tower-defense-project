### §59 CSV翻译文件en列为空导致tr()回退中文 🔴 高

**问题**: 切换语言到英文后，UI上仍显示中文文本。代码已正确使用tr()包装，但翻译不生效

**根因**: Godot的TranslationServer在加载CSV翻译文件时，如果某行的en列为空，tr()会回退到zh列的值（中文）。代码层tr()包装是必要但不充分的——CSV必须实际填充目标语言的翻译值

**解决方案**:
```gdscript
# ❌ 错误：en列为空
# key,zh,en
# TOWER_CHINESE_BASIC_NAME,语文之塔,

# ✅ 正确：en列必须填充
# key,zh,en
# TOWER_CHINESE_BASIC_NAME,语文之塔,Chinese Basics Tower
```

**预防**: 每次添加新翻译键时，必须同时填写zh和en两列；在CI/CD中添加CSV完整性检查脚本

**详细文档**: [Godot_4x_i18n_Pitfalls.md](../base/practical-experiences/pitfall-cases/Godot_4x_i18n_Pitfalls.md#坑1csv翻译文件en列为空导致tr回退中文-高)

### §60 重复代码导致i18n改造遗漏 🔴 高

**问题**: event_ui.gd的_format_requirements()已改为tr()调用，但切换英文后事件条件仍显示中文

**根因**: 存在两份功能相同的代码：event_ui.gd的_format_requirements()和option_system.gd的format_requirements()。UI层优先调用OptionSystem单例的方法，而OptionSystem中的方法仍是硬编码中文

**解决方案**:
```gdscript

else:
    req_text = _format_requirements(...)     # ← 只改了这条fallback

# ✅ 正确：全局搜索同名函数，确保所有副本都做i18n改造
# 搜索策略：func format_requirements、func _format_requirements
```

**预防**: 遵循DRY原则，格式化逻辑只在一个地方实现；新增i18n改造时，用全局搜索确认所有调用路径

### §64 _process中引用已释放对象导致崩溃 🔴 高

```gdscript
for button in flashing_buttons.keys():

    button.add_theme_stylebox_override("normal", style)
```

## 1️⃣9️⃣ AI辅助编辑工作流踩坑（§65）🆕

### §65 GDScript 缩进错误导致 Godot 编辑器崩溃 🔴 高

**问题**: 使用 `mcp_godot_edit_script` 或 `SearchReplace` 修改 GDScript 文件时，因缩进（tab）层级错误，导致代码逻辑结构被破坏，直接引发 Godot 编辑器崩溃

**根因分析**:

1. **GDScript 是缩进敏感语言**（与 Python 相同），缩进即逻辑，一个 tab 的差异就是"在循环内"还是"在循环外"的区别
2. **纯文本替换工具不理解语法结构**，`mcp_godot_edit_script` 和 `SearchReplace` 只机械匹配和替换字符串，不会校验缩进层级
3. **人脑数 tab 极易出错**，在构造 `new_snippet` 时靠人脑数 tab 来确定缩进层级，嵌套深时极易出错
4. **缺少读回验证步骤**，编辑后没有读回文件验证缩进是否正确，直接运行游戏导致崩溃

**实际案例**:

- **文件**: `autoload/i18n_manager.gd`
- **错误**: `file.close()` 多了一个 tab 缩进，从 `while` 循环外滑入循环内
- **后果**: 第一次循环就关闭文件，第二次循环读取已关闭文件，Godot 编辑器直接崩溃
- **修复**: 将 `file.close()` 缩进从循环内移到循环外（与 `while` 同级）

```gdscript
# ❌ 错误：file.close() 多了一个 tab，在 while 循环内部
while not file.eof_reached():
    var line: String = file.get_line()
    # ... 处理逻辑 ...
    file.close()  # ← 第一次循环就关闭文件！

# ✅ 正确：file.close() 与 while 同级，在循环外部
while not file.eof_reached():
    var line: String = file.get_line()
    # ... 处理逻辑 ...
file.close()  # ← 循环结束后才关闭
```

**必须遵守的规则**:

1. 🔴 **每次用 `edit_script` 或 `SearchReplace` 修改 GDScript 文件后，必须立即 Read 文件确认缩进正确**，然后才能运行测试
2. 🔴 **对于大段新增代码（如整个新方法），优先用 `Write` 工具写完整文件**，而非片段替换
3. 🔴 **如果用片段替换，先 Read 原文件确认上下文的精确缩进**，再构造替换内容
4. 🔴 **编辑流程必须是：编辑 -> 读回验证 -> 运行测试**，绝不能跳过读回验证步骤

**编辑工作流规范**:

```
标准流程（不可跳过任何步骤）：
1. Read 原文件 → 确认上下文精确缩进
2. 构造替换内容 → 逐行对比 tab 层级
3. 执行替换（edit_script / SearchReplace）
4. Read 修改后的文件 → 验证缩进正确
5. 运行测试 → 确认功能正常
```

## 2️⃣0️⃣ Area2D鼠标信号与并行交互系统踩坑（§66-§67）🆕

### §66 Area2D 鼠标信号不可靠 🔴 高

**问题**: Area2D 的 `mouse_entered`/`mouse_exited` 信号完全不触发，即使 `input_pickable=true`、`collision_layer/mask` 正确、`CollisionShape2D` 已添加且有效。`input_event` 中的 `InputEventMouseMotion` 也不触发，`InputEventMouseButton` 点击事件不稳定

**根因**: Godot 4 中 Area2D 的鼠标检测信号在特定场景下（CanvasLayer 叠加、Control 节点遮挡等）可能完全不工作，且无任何错误提示

**解决方案**:
```gdscript
# ❌ 错误：依赖 Area2D 鼠标信号做悬停检测
func _ready() -> void:
    mouse_entered.connect(func(): hovered.emit())  # 可能永远不触发！

# ✅ 正确：使用 _process + Rect2.has_point() 矩形碰撞检测
var is_mouse_hovering: bool = false
var hover_rect: Rect2

func _process(_delta: float) -> void:
    var mouse_pos: Vector2 = get_global_mouse_position()
    var was_hovering: bool = is_mouse_hovering
    is_mouse_hovering = hover_rect.has_point(mouse_pos)
    if is_mouse_hovering and not was_hovering:
        _on_mouse_entered()
    elif not is_mouse_hovering and was_hovering:
        _on_mouse_exited()
```

**规则**: 🔴强制 —— 禁止使用 Area2D 的 mouse_entered/mouse_exited/input_event 信号做鼠标悬停检测，必须使用 `_process()` 中的 `Rect2.has_point()` 或距离检测

**详细文档**: [Godot_4x_Area2D_Mouse_Signal_And_Parallel_Systems_Pitfall.md](../base/practical-experiences/pitfall-cases/Godot_4x_Area2D_Mouse_Signal_And_Parallel_Systems_Pitfall.md#66-area2d-的-mouse_enteredmouse_exited-信号不可靠--高)

### §67 多套并行交互系统导致隐蔽 Bug 🔴 高

**问题**: 项目中存在三套独立的 tooltip/悬停系统（MapManager轮询、TowerSelectUI信号、TooltipManager），战斗场景实际使用 MapManager 轮询，但开发者以为走的是 TowerSelectUI 信号路径，导致所有针对信号路径的修复都无效

**根因**: MapManager._update_tower_hover() 是每帧轮询检测鼠标位置的独立系统，完全绕过了 Tower 的 Area2D/信号系统。两套系统并存但互不通信，导致：1) Tower 的 is_mouse_hovering 在战斗场景永远为 false；2) 两套系统维护两份 tooltip 文本生成逻辑，翻译键 bug 只在其中一套出现；3) map_manager._show_tower_info() 中直接用了 `cfg.tower_name`（翻译键）而不是 `cfg.get_display_name()`（已翻译名）

```gdscript
# ❌ 错误：三套独立悬停系统并存
# MapManager 轮询、TowerSelectUI 信号、TooltipManager —— 互不通信

# ✅ 正确：同一交互功能只能有一条实现路径

# 2. 删除 TooltipManager 的独立逻辑
# 3. 只保留 MapManager 的轮询系统，但复用 TowerBean 的翻译方法

func _show_tower_info(tower: Tower) -> void:
    var cfg: TowerBean = tower.config
    var display_name: String = cfg.get_display_name()  # ✅ 复用翻译方法
    tooltip_label.text = display_name
```

**规则**: 🔴强制 —— 同一交互功能只能有一条实现路径，禁止"备用"或"并行"系统。如果需要重构，先删除旧系统再实现新系统，绝不允许两套并存

### §68 Python 原生手写 PNG 导致 Godot 导入失败 🔴 高

**问题**: 用 Python 原生 `struct+zlib` 手动构造 PNG 文件（IHDR+IDAT+IEND chunk），文件创建成功且其他图像查看器可打开，但 Godot 编辑器中全部显示红叉 ❌，7 个图标都无法识别

**根因**:
1. **PNG 格式不完整** —— 缺少 proper IHDR bit depth 字段、可能缺少其他必要 chunk
2. **Godot 导入系统兼容性严格** —— 原始生成的文件缺少必要的元数据，即使其他工具能打开，Godot 仍拒绝导入
3. **二进制格式细节问题** —— CRC 校验、过滤方法、zlib 压缩参数等可能不符合标准

**失败尝试历程**:

| 尝试 | 方案 | 失败原因 |
|------|------|----------|
| 尝试1 | Godot SceneTree 脚本 (--headless --script) | Autoload 单例初始化干扰（I18nManager、GameState 切换），脚本无法正常执行 |
| 尝试2 | Godot EditorScript | 需要 GUI 编辑器环境，--headless 模式不支持 |
| 尝试3 | Python 原生 struct+zlib 手写 PNG | 文件可被其他查看器打开，但 Godot 拒绝导入 |

**最终成功方案**: 使用 Python Pillow (PIL) 库

```python
# ✅ 正确：使用 Pillow 生成标准 RGBA PNG
from PIL import Image, ImageDraw
import os

os.makedirs("images/status_icons", exist_ok=True)

icons = {
    "status_slow":       ((51, 102, 230), "snow"),
    "status_dot":        ((230, 77, 26),   "fire"),
    "status_stun":       ((230, 230, 51),  "star"),
    "status_silence":    ((153, 77, 204),  "cross"),
    "status_confusion":  ((179, 102, 230), "?"),
    "status_armor_break":((204, 128, 26),  "shield"),
    "status_debuff":     ((128, 77, 77),   "down"),
}

SIZE = 20
CX = SIZE // 2
CY = SIZE // 2

for name, (rgb, shape) in icons.items():
    img = Image.new("RGBA", (SIZE, SIZE), (0, 0, 0, 0))
    draw = ImageDraw.Draw(img)
    draw.ellipse([1, 1, SIZE-2, SIZE-2], fill=(*rgb, 255),
                 outline=(*[max(0,c-60) for c in rgb], 200))
    # ... 各图标符号绘制 ...
    path = f"images/status_icons/{name}.png"
    img.save(path)
```

**结果**: Godot 自动为每个文件创建 `.import` 缓存，0 错误全部成功导入

**最佳实践**:

1. 🔴 **强制**: Godot 项目需要程序化生成图片时，优先使用 **Python Pillow/PIL**
2. 🔴 **强制**: 不要用 Python 原生 struct+zlib 手写 PNG 给 Godot 使用
3. 🟡 **建议**: Godot `--headless` 模式不适合运行依赖 Autoload 的工具脚本
4. 🟡 **建议**: 生成后需调用 `mcp_godot_rescan_filesystem` 让 Godot 重新扫描

**涉及文件**:
- `_gen.py` — Pillow 图标生成脚本
- `images/status_icons/*.png` — 7 个状态图标
- `scripts/view/enemy/enemy.gd` — 敌人状态图标显示逻辑
- `scripts/ui/target_info_panel.gd` — 目标信息面板倒计时显示

## 2️⃣2️⃣ UI程序化构建与数据格式踩坑（§69-§77）🆕

### §69 ColorRect 鼠标事件吞噬 🔴 高

**问题**: 添加 ColorRect 作为背景装饰后，其上层的所有 Button、Panel 等交互控件全部无法点击，鼠标事件被"吞噬"

**根因**: ColorRect 继承自 Control，默认 `mouse_filter = MOUSE_FILTER_STOP`，会拦截并消费所有经过它的鼠标事件（包括点击、悬停等），导致下层/上层控件收不到任何输入

```gdscript
# ❌ 错误：ColorRect 默认 MOUSE_FILTER_STOP 吞噬所有鼠标事件
var bg: ColorRect = ColorRect.new()
bg.color = Color(0.1, 0.1, 0.15, 0.95)
add_child(bg)  # 背景添加后，所有按钮无法点击！

# ✅ 正确：装饰性背景必须设置 IGNORE
var bg: ColorRect = ColorRect.new()
bg.color = Color(0.1, 0.1, 0.15, 0.95)
bg.mouse_filter = Control.MOUSE_FILTER_IGNORE  # 关键！让鼠标事件穿透
add_child(bg)
```

**规则**: 🔴 **强制** —— 任何作为纯装饰背景的 Control 节点（ColorRect、Panel 等），如果不需要接收鼠标输入，必须显式设置 `mouse_filter = Control.MOUSE_FILTER_IGNORE`

**常见误用场景**:
- 半透明遮罩背景
- 面板底色填充
- 分隔线/装饰条
- 全屏暗化效果

**来源**: 程序化构建 TraitSelectionUI 时添加背景 ColorRect 导致按钮全失灵

**相关规范**: [Godot 编码规范汇总 - 22.2 装饰性Control必须MOUSE_FILTER_IGNORE](./Godot%20编码规范汇总.md#222-装饰性-control-必须-mouse_filter_ignore--强制)

### §70 z-index 遮挡问题 🟡 中

**问题**: 动态创建的 UI 元素被其他面板覆盖，不可见或不可点击

**根因**: Godot 中 `add_child()` 的顺序决定渲染层级（z-index）。后添加的子节点渲染在上层（z 值更高）。如果先创建了弹出层的内容，再添加了背景遮罩，遮罩就会盖住内容

```gdscript
# ❌ 错误：先添加内容，再添加遮罩 → 遮罩盖住内容
func show_popup():
    var content: PanelContainer = _build_content()
    add_child(content)        # 先添加 → 在下层

    var overlay: ColorRect = ColorRect.new()
    overlay.color = Color(0, 0, 0, 0.5)
    add_child(overlay)       # 后添加 → 在上层，盖住 content！

# ✅ 正确：先添加底层元素，后添加顶层元素
func show_popup():
    var overlay: ColorRect = ColorRect.new()   # 底层：遮罩
    overlay.color = Color(0, 0, 0, 0.5)
    overlay.mouse_filter = Control.MOUSE_FILTER_IGNORE
    add_child(overlay)           # 先添加 → 在下层

    var content: PanelContainer = _build_content()
    add_child(content)           # 后添加 → 在上层

# ✅ 也正确：使用 move_child 调整层级
add_child(overlay)
add_child(content)
move_child(content, get_child_count())  # 移到最上层
```

**规则**: 🟡 **建议** —— 需要显示在最上层的 UI 元素应最后执行 `add_child()`；或使用 `move_child(node, get_child_count())` 强制调整到顶层

**注意**: 这不是 CSS z-index 那样可以任意设置数字值，Godot 的渲染顺序严格遵循子节点在树中的顺序

**相关规范**: [Godot 编码规范汇总 - 22.3 add_child顺序即渲染层级](./Godot%20编码规范汇总.md#223-add_child-顺序即渲染层级--建议)

### §71 offset vs MarginContainer 🟡 中

**问题**: 使用 `offset_left/right/top/bottom` 创建面板内边距时，导致内容被裁剪或位置异常

**根因**: offset 是节点自身的偏移量（相对于父容器锚点的位移），不是容器内的 padding。在 Container 子节点中设置 offset 会被容器的布局规则覆盖或导致意外行为

```gdscript
# ❌ 错误：用 offset 模拟内边距
var panel: PanelContainer = PanelContainer.new()
panel.offset_left = 20    # 在 Container 中可能无效或产生异常布局
panel.offset_right = -20
panel.offset_top = 10
panel.offset_bottom = -10
add_child(panel)
# 结果：内容位置异常或被裁剪

# ✅ 正确：使用 MarginContainer 设置统一内边距
var margin: MarginContainer = MarginContainer.new()
margin.add_theme_constant_override("margin_left", 20)
margin.add_theme_constant_override("margin_right", 20)
margin.add_theme_constant_override("margin_top", 10)
margin.add_theme_constant_override("margin_bottom", 10)
add_child(margin)

var inner_panel: PanelContainer = PanelContainer.new()
margin.add_child(inner_panel)  # 内边距由 MarginContainer 管理
```

**规则**: 🟡 **建议** —— 创建面板间留白统一使用 `MarginContainer + theme constant override`，不使用 `offset` 模拟内边距

**适用场景**:
- 弹窗内边距
- 列表项间距
- 内容区域留白
- 多列面板之间的间隔

**相关规范**: [Godot 编码规范汇总 - 22.4 面板留白用MarginContainer不用offset](./Godot%20编码规范汇总.md#224-面板留白用-margincontainer-不用-offset--建议)

### §72 Signal 重复连接 🟡 中

**问题**: 热重载时报错 `"Signal is already connected to the method"` 或同一回调被多次触发

**根因**: GDScript 中 `signal.connect(callback)` 如果对已连接的信号再次调用 connect，Godot 4.x 会报错（而非静默忽略）。热重载时会重新执行 `_ready()`，导致信号被重复连接

```gdscript
# ❌ 错误：直接 connect，热重载时重复连接报错
func _ready() -> void:
    some_signal.connect(_on_callback)  # 热重载第二次执行时报错！

# ✅ 正确：连接前用 is_connected() 守卫检查
func _ready() -> void:
    if not some_signal.is_connected(_on_callback):
        some_signal.connect(_on_callback)

# ✅ 完整安全模式（推荐）
func _connect_signals() -> void:
    if not some_button.pressed.is_connected(_on_button_pressed):
        some_button.pressed.connect(_on_button_pressed)
    if not some_signal.some_callback.is_connected(_on_callback):
        some_signal.some_callback.connect(_on_callback)
```

**规则**: 🔴 **强制** —— 所有 `signal.connect()` 调用前必须有 `is_connected()` 守卫检查，防止热重载导致的重复连接错误

**相关规范**: [Godot 编码规范汇总 - 22.5 Signal连接安全模式](./Godot%20编码规范汇总.md#225-signal-连接安全模式--强制)

```gdscript
var trait_id: String = trait_data.get("trait_id", "")  # 与 JSON 一致

# ✅ 更好：通过配置系统单例获取，避免硬编码字段名
var trait_cfg: Dictionary = TraitSystem.get_trait_config(trait_id_str)
```

### §74 tr() 格式化参数类型 🟡 中

**问题**: GDScript 中使用 `% string` 对 `tr()` 返回值进行格式化，但替换不生效，显示原始占位符

**根因**: GDScript 的字符串格式化操作符 `%` 要求右侧参数为数组类型（`Array`），传单个值不会正确替换

```gdscript
# ❌ 错误：传单个参数，格式化不生效
var text: String = tr("DAMAGE_FORMAT") % damage_value  # 显示 "{0}" 而非实际值
var label: String = tr("ATTR_FORMAT") % "intelligence"  # 显示 "%s" 而非 "intelligence"

# ✅ 正确：tr() 的 % 格式化必须传数组参数
var text: String = tr("DAMAGE_FORMAT") % [damage_value]          # 数组包裹
var label: String = tr("ATTR_FORMAT") % [display_name, value]     # 多参数也用数组
var hint: String = tr("REQ_HAS_TRAIT") % [trait_name]             # 单参数也要数组
```

**规则**: 🔴 **强制** —— `tr()` 的 `%` 格式化操作符右侧**必须传递数组** `[arg1, arg2, ...]`，即使只有一个参数也不能省略方括号

**相关规范**: [Godot 编码规范汇总 - 22.8 动态文本必须i18n](./Godot%20编码规范汇总.md#228-动态文本必须-i18n--强制)

**CSV 翻译文件中的对应格式**:
```csv
# translations.csv
DAMAGE_FORMAT,伤害：%d,Damage: %d
ATTR_FORMAT,%s：%+d,%s: %+d
REQ_HAS_TRAIT,拥有「%s」,Has %s
```

### §75 Godot 内置 tooltip 延迟 🟡 中

**问题**: 使用 `Control.tooltip_text` 属性设置提示文本后，鼠标悬停约 0.5~1 秒才弹出 tooltip，用户体验不够即时

**根因**: Godot 内置 tooltip 机制设计用于辅助说明，有固定的延迟时间（由 Project Settings > GUI > Tooltips > Delay (sec) 控制），不适合需要即时反馈的场景

```gdscript
# ❌ 错误：内置 tooltip 有 ~0.5-1s 延迟
var badge: TextureButton = TextureButton.new()
badge.tooltip_text = "塔伤害+15%"  # 用户悬停后要等很久才看到

# ✅ 正确：自定义 PopupPanel + mouse_entered/mouse_exited 实现即时弹出
extends Control

var _tooltip_popup: PopupPanel
var _tooltip_label: Label

func _ready() -> void:
    _create_custom_tooltip()

    # 连接目标控件的鼠标进出信号
    target_control.mouse_entered.connect(_show_tooltip)
    target_control.mouse_exited.connect(_hide_tooltip)

func _create_custom_tooltip() -> void:
    _tooltip_popup = PopupPanel.new()
    _tooltip_popup.mouse_filter = Control.MOUSE_FILTER_IGNORE

    var style: StyleBoxFlat = StyleBoxFlat.new()
    style.bg_color = Color(0.15, 0.15, 0.2, 0.95)
    style.border_color = Color(0.4, 0.4, 0.5, 0.8)
    style.set_border_width_all(1)
    style.set_corner_radius_all(4)
    _tooltip_popup.add_theme_stylebox_override("panel", style)

    _tooltip_label = Label.new()
    _tooltip_label.mouse_filter = Control.MOUSE_FILTER_IGNORE
    _tooltip_popup.add_child(_tooltip_label)

    add_child(_tooltip_popup)

func _show_tooltip() -> void:
    _tooltip_label.text = _format_tooltip_text()
    var global_pos: Vector2 = get_global_mouse_position() + Vector2(10, 10)

    # 边界检测：防止超出屏幕
    var popup_size: Vector2i = _tooltip_popup.get_minimum_size()
    var screen_size: Vector2i = DisplayServer.window_get_size()
    if global_pos.x + popup_size.x > screen_size.x:
        global_pos.x = screen_size.x - popup_size.x - 5
    if global_pos.y + popup_size.y > screen_size.y:
        global_pos.y = global_pos.y - popup_size.y - 25  # 移到上方

    _tooltip_popup.position = global_pos
    _tooltip_popup.popup()

func _hide_tooltip() -> void:
    _tooltip_popup.hide()
```

**规则**: 🟡 **建议** —— 需要即时反馈的悬停提示（如词条效果预览、属性详情）不用内置 `tooltip_text`，改用 `PopupPanel + mouse_entered/mouse_exited` 自定义实现

**相关规范**: [Godot 编码规范汇总 - 22.6 自定义即时Tooltip模式](./Godot%20编码规范汇总.md#226-自定义即时-tooltip-模式--建议)

**自定义 Tooltip 优势**:
- 即时响应（无延迟）
- 支持富文本（RichTextLabel）
- 完全控制样式和动画
- 可精确控制位置和边界检测

### §76 效果类型 match 遗漏 🟡 中

**问题**: 词条效果的 tooltip 显示原始字典内容 `{type: tower_damage_bonus, value: 0.15}` 而非格式化后的可读文本

**根因**: `_format_effect()` 函数的 `match effect_type` 语句只处理了部分已知效果类型，新增的效果类型落入 `_:` 兜底分支，直接输出了原始字典

```gdscript
# ❌ 错误：match 兜底分支输出原始数据
func _format_effect(effect: Dictionary) -> String:
    match effect.get("type", ""):
        "tower_damage_bonus":
            return "塔伤害+%.0f%%" % [val * 100]
        "tower_attack_speed_bonus":
            return "攻速+%.0f%%" % [val * 100]
        _:  # 新增效果类型全部落入这里！
            return str(effect)  # 显示 {type: xxx, ...} 原始字典

# ✅ 正确：
# 1. 补全所有已知效果类型的 match 分支
# 2. 兜底分支给出有意义的降级显示
func _format_effect(effect: Dictionary) -> String:
    var effect_type: String = effect.get("type", "")
    var val: float = effect.get(effect_type, effect.get("value", 0))
    match effect_type:
        "tower_damage_bonus":
            return tr("TOWER_DAMAGE_BONUS") % [val * 100]
        "tower_attack_speed_bonus":
            return tr("TOWER_ATTACK_SPEED_BONUS") % [val * 100]
        "enemy_slow":
            return tr("ENEMY_SLOW_EFFECT") % [val * 100]
        "enemy_dot":
            return tr("ENEMY_DOT_EFFECT") % [val * 100]
        "attribute_bonus":
            var attr_name: String = effect.get("attribute", "")
            return tr("ATTRIBUTE_BONUS") % [tr("ATTR_" + attr_name.to_upper()), val]
        "gold_bonus":
            return tr("GOLD_BONUS") % [int(val)]
        _:
            # 兜底：至少显示 type 和数值，不要暴露原始字典
            push_warning("未知效果类型: %s" % effect_type)
            return tr("UNKNOWN_EFFECT") % [effect_type, val]
```

**规则**: 🟡 **建议** —— `match` 语句的 `_:` 兜底分支不应输出原始数据（如 `str(dictionary)` / `str(object)`）；应给出有意义的降级显示或至少输出关键可读信息，同时发出 `push_warning` 提醒开发者补充处理

**相关规范**: [Godot 编码规范汇总 - 22.7 match语句兜底规范](./Godot%20编码规范汇总.md#227-match-语句兜底规范--建议)

### §77 属性名国际化缺失 🟡 中

**问题**: 词条效果显示 `attribute_bonus: intelligence +8` 而非翻译后的 `智力 +8`，用户看到的是英文属性 key 而非本地化名称

**根因**: 属性名字段（如 `intelligence`、`strength`、`agility`）直接拼接进显示文本，未经过 `tr()` 翻译键映射

```gdscript
# ❌ 错误：直接使用属性 key，未翻译
var attr_name: String = effect.get("attribute", "unknown")
text = "%s +%d" % [attr_name, value]  # 显示 "intelligence +8"

# ✅ 正确：属性 key 映射到翻译键 ATTR_{KEY}
var attr_name: String = effect.get("attribute", "unknown")
var translated_attr: String = tr("ATTR_" + attr_name.to_upper())  # ATTR_INTELLIGENCE
text = tr("ATTRIBUTE_BONUS") % [translated_attr, value]  # 显示 "智力 +8"
```

**CSV 翻译键对照表**:
```csv
# translations.csv
ATTR_INTELLIGENCE,智力,Intelligence
ATTR_STRENGTH,力量,Strength
ATTR_AGILITY,敏捷,Agility
ATTR_CONSTITUTION,体质,Constitution
ATTRIBUTE_BONUS,%s +%d,%s +%d
```

**规则**: 🔴 **强制** —— 所有用户可见文本必须经过 `tr()` 翻译，包括动态生成的属性名、效果名等。枚举/key 到翻译键的映射模式为：`TR("{CATEGORY}_{KEY}".to_upper())`

**相关规范**: [Godot 编码规范汇总 - 22.8 动态文本必须i18n](./Godot%20编码规范汇总.md#228-动态文本必须-i18n--强制)

**完整 i18n 效果格式化示例**:
```gdscript
func _format_effect_i18n(effect: Dictionary) -> String:
    var effect_type: String = effect.get("type", "")
    var val: float = effect.get(effect_type, effect.get("value", 0))

    match effect_type:
        "tower_damage_bonus":
            return tr("EFFECT_TOWER_DMG") % [val * 100]
        "attribute_bonus":
            var attr_key: String = effect.get("attribute", "")
            var attr_display: String = tr("ATTR_" + attr_key.to_upper())
            return tr("EFFECT_ATTR_BONUS") % [attr_display, int(val)]
        "gold_bonus":
            return tr("EFFECT_GOLD_BONUS") % [int(val)]
        _:
            push_warning("未知效果类型: %s" % effect_type)
            return tr("EFFECT_UNKNOWN") % [effect_type, val]
```

### §78 apply_buff 复合修改 config 导致 Timer 报错 🔴 高

**问题**: `tower.gd:apply_buff()` 直接修改共享的 `attack_component.config.damage` 和 `attack_component.config.attack_speed`，由于 config 是同一对象引用，每帧从 `_update_auras()` 调用 `apply_buff()` 导致值复合增长：`config.damage = config.damage * (1 + bonus)`，attack_speed 趋向无穷大，`wait_time = 1/speed -> 0`，触发 Timer "Time should be greater than zero" 报错。

**根因**: Resource 对象在 Godot 中是引用语义，`attack_component.config` 与 `tower.config` 是同一对象。直接修改共享 config 的属性作为运行时状态，每帧乘法导致指数级增长。

**解决方案**:
```gdscript
# ❌ 错误：直接修改共享 config，每帧复合增长
func apply_buff(buff_dmg: float, buff_spd: float) -> void:
    attack_component.config.damage *= (1.0 + buff_dmg)    # 每帧乘！
    attack_component.config.attack_speed *= (1.0 + buff_spd)  # 指数增长！
    attack_component.setup_timer()

# ✅ 正确：保存基础值，从基础值计算有效值
var _base_damage: float = 0.0
var _base_attack_speed: float = 0.0

func setup_tower() -> void:
    _base_damage = config.damage
    _base_attack_speed = config.attack_speed

func apply_buff(buff_dmg: float, buff_spd: float) -> void:
    var effective_dmg: float = _base_damage * (1.0 + buff_dmg)
    var effective_spd: float = _base_attack_speed * (1.0 + buff_spd)
    attack_component.setup_timer_with_buffs(effective_dmg, effective_spd)
```

**规则**: 🔴 **强制** —— 永远不要直接修改共享的 config/resource 对象的属性值作为运行时状态，应保存基础值副本，从基础值 + bonus 计算有效值。

**涉及文件**: `scripts/view/tower/tower.gd`, `scripts/view/tower/tower_attack_component.gd`

**相关规范**: [Godot 编码规范汇总 - 23.1 共享资源对象不可变原则](./Godot%20编码规范汇总.md#231-共享资源对象不可变原则--强制)

**详细文档**: [Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md](../base/practical-experiences/pitfall-cases/Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md#78-apply_buff-复合修改-config-导致-timer-报错--高)

### §79 暴击伤害计算未包含 trait 加成 🔴 高

**问题**: 暴击塔的伤害数值明显低于预期。`effect_system.gd:_apply_crit()` 使用 `source_tower.config.damage * multiplier` 计算暴击伤害，但 `config.damage` 是基础伤害值，不包含 trait 加成。而正常攻击使用 `config.damage * (1 + trait_bonus)` 计算实际伤害，导致暴击伤害 = 基础伤害 x 暴击倍率，而非 实际伤害 x 暴击倍率。

**根因**: 伤害计算逻辑散布在多个方法中，新增的伤害类型（暴击）遗漏了 trait 加成。

**解决方案**:
```gdscript
# ❌ 错误：暴击只用基础伤害，遗漏 trait 加成
func _apply_crit(source_tower: Tower, target: Node2D, multiplier: float) -> void:
    var crit_damage: float = source_tower.config.damage * multiplier  # 缺少 trait！

# ✅ 正确：使用与攻击方法相同的伤害公式
func _apply_crit(source_tower: Tower, target: Node2D, multiplier: float) -> void:
    var base_dmg: float = source_tower.config.damage
    var ts: Node = get_node_or_null("/root/TraitSystem")
    var trait_bonus: float = 0.0
    if ts and ts.has_method("get_trait_effects_for_tower"):
        trait_bonus = ts.get_trait_effects_for_tower(source_tower.config.tower_id)
    var effective_dmg: float = base_dmg * (1.0 + trait_bonus)
    var crit_damage: float = effective_dmg * multiplier
```

**规则**: 🔴 **强制** —— 所有伤害计算必须使用与攻击方法相同的公式（含 trait 加成、buff 加成等），保持一致性。

**涉及文件**: `scripts/logic/tower_defense/effect_system.gd`

**相关规范**: [Godot 编码规范汇总 - 23.2 伤害计算一致性原则](./Godot%20编码规范汇总.md#232-伤害计算一致性原则--强制)

**详细文档**: [Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md](../base/practical-experiences/pitfall-cases/Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md#79-暴击伤害计算未包含-trait-加成--高)

### §80 add_theme_stylebox_override vs set_theme_stylebox_override 🔴 高

**问题**: 调用 `set_theme_stylebox_override()` 报错 `Invalid call. Nonexistent function 'set_theme_stylebox_override' in base 'Button'`。

**根因**: Godot 4.x 正确 API 是 `add_theme_stylebox_override()`，不存在 `set_theme_stylebox_override()`。这是 Godot 3.x -> 4.x 的 API 变更，Godot 4 统一使用 `add_theme_*_override` 系列方法。

**解决方案**:
```gdscript
# ❌ 错误：Godot 3.x API
button.set_theme_stylebox_override("normal", style)

# ✅ 正确：Godot 4.x API
button.add_theme_stylebox_override("normal", style)
```

**Godot 4.x 主题覆盖 API 完整列表**:

| 类型 | 方法 | 用途 |
|------|------|------|
| StyleBox | `add_theme_stylebox_override(name, stylebox)` | 覆盖样式盒 |
| Color | `add_theme_color_override(name, color)` | 覆盖颜色 |
| Font | `add_theme_font_override(name, font)` | 覆盖字体 |
| FontSize | `add_theme_font_size_override(name, size)` | 覆盖字号 |
| Constant | `add_theme_constant_override(name, constant)` | 覆盖常量 |

**规则**: 🔴 **强制** —— Godot 4.x 中覆盖主题属性统一使用 `add_theme_*_override()` 系列方法，不存在 `set_theme_*_override()` 方法。

**涉及文件**: `scripts/ui/target_info_panel.gd`

**相关规范**: [Godot 编码规范汇总 - 23.3 主题覆盖 API 规范](./Godot%20编码规范汇总.md#233-主题覆盖-api-规范--强制)

**详细文档**: [Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md](../base/practical-experiences/pitfall-cases/Godot_4x_Buff_Crit_ThemeOverride_Pitfalls.md#80-add_theme_stylebox_override-vs-set_theme_stylebox_override--高)
