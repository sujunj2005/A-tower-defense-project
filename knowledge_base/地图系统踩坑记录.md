# 地图系统踩坑记录

## 1. MapConfig Resource 格式不适合 xlsx 表格化

**问题:** 地图数据包含大量嵌套结构（Array[Vector2i]、Rect2、Dictionary），强行导出成 xlsx 列数爆炸，难以使用。
**解决:** 地图继续用 .tres Resource 格式，config_tool.py 不处理地图文件。
**来源:** map_config.gd, config_tool.py

## 2. 目录扫描注册表实现

**问题:** _static_init() 中硬编码注册表不便于扩展。
**解决:** 使用 DirAccess.open() 扫描 res://resources/maps/ 目录，从文件名推导 map_id。需保留 fallback 到硬编码注册表（扫描失败时）。
**踩坑:** DirAccess.list_dir_begin() 后必须调用 list_dir_end()，否则可能泄漏。扫描时只处理 .tres 后缀，需验证 Resource 类型是 MapConfig。
**来源:** map_config.gd _scan_maps_directory()

## 3. 地图权重累加时机

**问题:** 地图权重何时累加、何时选图、何时清空？
**解决:** select_option() 时累加权重到 session.accumulated_map_weights，_trigger_battle() 时选图并清空。force_map_id 覆盖权重选择。
**踩坑:** 异常退出可能导致 accumulated_map_weights 脏数据，但该字段非持久化（无 @export），新游戏自动清空。
**来源:** event_system.gd select_option(), _trigger_battle()

## 4. 敌人属性缩放时机

**问题:** 难度倍率何时应用到敌人属性？
**解决:** 在 MapManager._on_enemy_spawn_requested() 中，enemy.initialize() 之后直接修改 enemy.current_health。不修改共享的 EnemyConfig 对象。
**踩坑:** initialize() 设置 current_health = config.max_health，之后需重新赋值。health_bar.max_value 也需同步更新。damage_multiplier 在 MapManager._on_enemy_reached_base() 中乘以 config.damage。
**来源:** map_manager.gd _on_enemy_spawn_requested(), enemy.gd

## 5. waypoints 路径计算限制

**问题:** MapConfig.compute_path_from_waypoints() 仅支持水平/垂直移动。
**解决:** 设计地图 waypoints 时确保相邻 waypoint 之间只有水平或垂直移动，不支持对角线。
**来源:** map_config.gd compute_path_from_waypoints()

## 6. 全局难度配置读取

**问题:** game_config.json 的 difficulty_presets 如何在 MapManager 中读取？
**解决:** 通过 ConfigManager.load_json() 读取，根据 session.global_difficulty 选择预设。ConfigManager 是 autoload 单例。
**来源:** map_manager.gd _get_difficulty_multipliers()
